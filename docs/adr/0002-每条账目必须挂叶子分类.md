# ADR-0002 每条账目必须挂叶子分类

日期：2026-10-04　状态：已采纳（用户决定）

## 背景

需求与分类文档原写“不计收支类型使用记录类型和用途字段”，但工程契约无此字段，初始分类也无对应目录。

## 决定

1. **所有正式账目与候选都必须引用一个有效叶子分类**，不存在无分类条目。`leaf_category_id` 在 Entry 中为必填。
2. 分类目录的 `kind` 扩展为六种：`expense`、`income`、`internal_transfer`、`exchange`、`card_repayment`、`receivable`。
3. 记录类型与可选目录的对应：

| 记录类型 | 分类 kind |
|---|---|
| expense 支出 | expense |
| refund 退款 | 不可自选，强制等于原消费的叶子（随原消费分类重定向解析） |
| income 收入 | income |
| internal_transfer 内部转账 | internal_transfer |
| exchange 换汇 | exchange |
| card_repayment 信用卡还款 | card_repayment |
| receivable 往来款 | receivable |

4. 初始不计收支目录（见 `seed/categories.json`）：
   - 内部转账：账户间转账、现金存取、其他内部转账
   - 换汇：货币兑换
   - 信用卡还款：信用卡还款
   - 往来款：借出、收回借款、借入、归还借款、代垫、收回代垫、其他往来
5. 不计收支目录同样可由家庭管理员改名、新增、移动、合并、停用、删除；移动／合并禁止跨 kind。
6. 不计收支目录不参与收入、支出、饼图和消费方式统计；Dashboard 列表照常显示一级／二级分类。往来款子类仅用于查看，第一版不计算债权余额（需求 4.1 不变）。
7. AI 可为不计收支类型选择对应目录叶子；无法判断时，支出／收入用各自“待分类”，不计收支用该目录的“其他”类叶子（换汇、信用卡还款只有一个叶子）。

## 影响

- 需求 4.2 的“一级／二级分类”对所有类型必填；分类规则 §2 末段被本 ADR 取代。
- 新增验收：CAT-04（类型与 kind 不匹配被拒绝）、ACC-08 补充“不计收支目录显示但不参与统计”。
