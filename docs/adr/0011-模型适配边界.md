# ADR-0011 模型适配边界与分层结果

日期：2026-10-04　状态：已采纳　依据：工程契约 §5、架构 §5、ISE-004／005／006／019

## 决定

### 适配器接口

`RecognitionModel.extract(request) -> ModelAttempt`，只返回候选数据、usage 与错误类别，不持有任何数据库写能力。请求只含：当前用户提交的文字（≤300 字）／一张已校验图片的模型输入副本、当前家庭有效叶子分类 ID 与名称、请求接收日的家庭日历日期、家庭默认值说明。不含其他家庭数据、用户 ID、family ID。

### 处理顺序

1. 调用前：校验输入大小与格式、Job 尝试预算（每 Job 实际模型调用 ≤2，含 SDK 重试；SDK 自动重试关闭，由应用计数）、剩余期限（Worker 总期限 90 秒）。
2. 供应商响应：拆开 envelope、stop reason、内容块、usage。stop reason 为截断（max_tokens 等）→ `protocol_error`，不尝试解析部分 JSON。
3. 协议解析：只接受单个文本内容块；整体为 JSON 或整体被单个 Markdown 代码围栏包裹；拒绝重复键（`object_pairs_hook` 检测）、NaN／Infinity、尾随内容。
4. Schema 校验：`contracts/model.schema.json`。
5. 语义校验：`category_id` 属于本次请求提供的有效叶子集合且 kind 与 type 对应；日期不晚于请求接收日＋1；币种为家庭启用币种；`missing_fields` 与 null 字段一致。不通过的单个字段置 null 并加入 `missing_fields`／`needs_review`，整体结构错误则 `semantic_invalid`。
6. 应用补默认值（`family_default`／`request_date` 来源标注），计算 fx 预览，发布候选（T13，含当前权限与 fencing 复核）。

### 分层结果（分别记录，不互相推断）

| 层 | 字段 | 说明 |
|---|---|---|
| 请求返回 | `outcome.request_returned` | 供应商返回了响应 |
| 协议／Schema | `outcome.schema_valid` | 通过步骤 3、4 |
| 语义 | `outcome.semantic_valid` | 通过步骤 5 |
| 发布 | `outcome.published` | T13 已提交 |
| 用户确认／入账 | 候选 `status=confirmed`＋ActionReceipt | 确认事务提交 |
| 外部交付 | Outbox `delivery` 状态 | 飞书卡片／回执 |

事实正确性（金额是否与小票一致）不由系统自动判断，由用户确认环节和离线质量评估（QUAL-01）衡量。

### 错误分类

`input_rejected`（输入不合规，不调用模型）、`auth_error`（工作负载凭证）、`permission_revoked`（用户已失去权限）、`rate_limited`、`transport_error`、`timeout`、`protocol_error`、`schema_invalid`、`semantic_invalid`、`attempts_exhausted`、`internal`。只有 `rate_limited`、`transport_error`、`timeout` 在预算内可重试；格式类错误不付费重试。

### usage 与版本

每次尝试记录 known tokens；超时、传输中断等无 usage 的尝试计入 `unknown_usage_calls`，不补零。Job 绑定 `model_id`、`prompt_version`、`schema_version`、`config_version`，评估与回归按此分组。
