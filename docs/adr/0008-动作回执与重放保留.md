# ADR-0008 动作回执与外部重放保留

日期：2026-10-04　状态：已采纳

## 决定

1. **ActionReceipt** 以 `(family, actor, idempotency_key)` 为键，与业务写入在同一 DynamoDB 事务中创建。内容只含动作种类、请求指纹（SHA-256，覆盖动作种类、对象 ID、family、actor、规范化正文）、状态、结果对象 ID 与版本、时间；**不含备注、金额等业务正文**。
2. 回执**永久保留**（体积小，不含私人正文），因此任何时间重放旧 key 都返回原结果，不会重新产生账目。账目被清理后，回执仍返回 `result_purged: true` 与原 ID。
3. 不使用 TTL 删除回执；DynamoDB 客户端 token 窗口不作为去重依据。
4. **候选确认**：确认动作把候选标记为 `confirmed` 并记录 entry ID；候选 7 天到期后，过期／未确认的候选进入 `expired`，候选项保留最小状态（ID、状态、版本、结果 entry ID）至少 400 天，正文在到期后清除。重复确认已确认候选返回原回执；确认已过期候选返回 `candidate_expired`。
5. **飞书事件**：Inbox 以平台 `event_id` 去重，保留 30 天（远大于平台重试窗口，D4 核实官方值后调整）。卡片动作的 action ID 由服务端生成于卡片发送时（绑定 candidate ID＋版本＋动作），因此重复点击、重复投递均命中同一回执。
6. **进行中竞态**：客户端在原请求尚未提交时查询得到 404 并以同一 key 重试，两次请求的事务都包含 `ACTION#` 的 `attribute_not_exists` 条件，至多一个提交；落败方读取已提交回执并按指纹返回原结果或 409。404 只来自强一致读取，查询失败（超时、5xx）保持 unknown。
7. **消息、任务与业务键分离（ISE-016）**：飞书 `event_id` 只用于事件去重；Job 的业务键为 `(tenant, message_id)`，`job_id` 由其确定性派生，因此平台以不同 event_id 重投同一消息也只产生一个 Job。网站识别的 Job 业务键为 `(actor, Idempotency-Key)`。SQS 消息 ID 与接收次数不作为业务尝试次数，模型尝试次数记在 Job 上。
8. 同 key 不同指纹返回 409 `idempotency_key_reused`；客户端不得换 key 重试未知结果，必须先 `GET /actions/{key}`。
