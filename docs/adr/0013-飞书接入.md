# ADR-0013 飞书接入协议与流程

日期：2026-10-04　状态：已采纳（离线实现）；真实协议细节待 D4 实测　依据：需求 §6.3、架构 §2.3、ISE-005／012／014／016／018

## 已从官方文档核实（2026-10-04）

| 项 | 核实结果 | 来源 |
|---|---|---|
| 请求签名 | `X-Lark-Signature` ＝ sha256(`X-Lark-Request-Timestamp` ＋ `X-Lark-Request-Nonce` ＋ Encrypt Key ＋ 原始 body) 的十六进制 | 事件订阅加密配置 |
| 事件解密 | AES-256-CBC；密钥 ＝ sha256(Encrypt Key)；base64 解码后前 16 字节为 IV；PKCS7；密文在 `encrypt` 字段 | 同上 |
| 接收消息 | `im.message.receive_v1`，schema 2.0；`header.event_id／token／app_id／tenant_key`；`event.sender.sender_id.open_id`、`sender_type`；`event.message.message_id／parent_id／chat_type(p2p|group)／message_type／content(JSON 字符串)`；**官方建议以 message_id 去重而非 event_id** | 接收消息 |
| 卡片回调 | `card.action.trigger`；`event.operator.open_id`；`event.action.value／form_value／option`；`event.context.open_message_id`；**须 3 秒内响应**；响应可含 `toast`（info/success/error/warning）与 `card`（raw／template）；`event.token` 30 分钟内最多更新卡片 2 次 | 卡片回调通信 |
| 发送消息 | `POST /open-apis/im/v1/messages?receive_id_type=open_id`，body `receive_id／msg_type=interactive／content(JSON 字符串)／uuid`；**同一 uuid 1 小时内最多成功发送一次**；单用户 5 QPS | 发送消息 |
| 卡片回调时间戳（2026-10-04 生产实测） | `X-Lark-Request-Timestamp` 为 Go 时间字符串（如 `2026-10-04 18:23:46.052290112 +0800 CST `，含尾部空格），而事件回调为 Unix 秒；签名仍为 64 位 sha256，按原始头部字符串计算 | 生产日志 |
| 下载图片 | `GET /open-apis/im/v1/messages/{message_id}/resources/{file_key}?type=image`；机器人须在同一会话；图片 <100 MB，返回二进制 | 获取消息中的资源文件 |

## 尚未核实（D4 真实联调时确认，不伪造）

- URL 验证请求在加密模式下的确切结构：2026-10-04 生产实测加密验证请求可被解密并通过（实现同时接受 `encrypt`／`encrypted` 字段，无签名头时只回显 challenge）。
- 卡片 JSON 2.0 中表单、`select_static`、`date_picker`、`input`、回调按钮的确切字段；以飞书卡片搭建工具校验。
- `tenant_access_token` 获取接口与缓存时长、错误码；回调签名在卡片回调上是否与事件订阅一致。
- 两位用户是否在同一企业租户（企业自建应用只服务本租户）。
- 冷启动下卡片回调能否稳定在 3 秒内（FS-06）。

## 决定

1. **身份只来自平台可信字段**：消息用 `sender.sender_id.open_id`＋`header.tenant_key`；卡片用 `operator.open_id`。经 `FSID#<tenant>#<open_id>` 映射到内部用户；卡片 `value` 中的 family、candidate 等只作为定位参数，授权一律按映射用户的当前成员关系判断（AUTH-08／10）。
2. **入口校验顺序**：签名 → 时间戳新鲜度（±5 分钟，防重放）→ 解密 → `token`＝Verification Token → `app_id`／`tenant_key` 白名单 → 事件去重。任何一步失败返回 401 或忽略，不读取资源、不调用模型（FS-02）。
3. **去重**：事件以 `event_id` 去重（`FSEVT#`，30 天）；识别 Job 以 `(tenant, message_id)` 确定性派生（ADR-0008 第 7 条），重投同一消息只产生一个 Job。
4. **绑定**：网站登录后生成 8 位一次性绑定码（10 分钟，只存哈希）；用户在私聊发送“绑定 XXXXXXXX”。码用后即失效；不按昵称匹配（FS-01）。改密／重置后绑定置为 suspended，需重新绑定。
5. **只处理私聊**：`chat_type=p2p` 且 `sender_type=user`；群消息、机器人消息忽略。
6. **文字与图片关联**：单条图片消息即为“仅图片”识别；文字消息若是对某条图片消息的回复（`parent_id`），与该图片合并识别；不按时间邻近自动拼接（FS-03）。图片由 Worker 通过资源接口下载，按网站同样规则校验后存为照片凭证。
7. **卡片内完成编辑与确认**：每个批次一张卡片，显示家庭、日期、类型、币种、金额、两级分类、方式、备注、默认值提示与折算；支持编辑（表单）、一级分类切换刷新二级选项、逐条确认、全部确认、取消。确认走与网站相同的 `candidates.confirm`，动作 ID 在卡片构建时由服务端按（批次、候选、版本、动作）确定性生成，重复点击命中同一回执（FS-05）。
8. **交付与入账分离**：卡片发送通过 outbox；记录 `delivery`＝pending／sent（附 message_id）／failed／unknown。发送超时为 unknown，重试使用同一 `uuid`（1 小时去重窗口）；超出窗口不再自动重发，管理页可见。入账状态从不因卡片发送失败而改变（FS-07）。**投递时机**：Relay 由 DynamoDB Streams 触发时立即投递到期消息，5 分钟定时任务只作兜底（2026-10-04 首次联调发现原实现只靠定时任务，回复最慢 5 分钟）。
9. **3 秒限制**：卡片回调同步完成编辑／确认并直接返回新卡片；若实测冷启动超时，改为先回 toast“处理中”，再用 `event.token` 异步更新（不提前报成功，FS-06）。
10. **离线替身**：`ledger.local.feishu` 记录发送的消息与卡片，并能构造带签名、加密的回调用于测试；不作为真实协议证据。
