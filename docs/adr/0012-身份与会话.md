# ADR-0012 身份、会话与登录名

日期：2026-10-04　状态：已采纳　依据：需求 §3.1、架构 §4.1、ISE-012／015

## 决定

1. **登录名由应用解析**：`/auth/login` 先查 `LOGIN#<小写登录名>` 得到固定 `user_id`，再以 `user_id` 作为身份服务内部用户名认证（Cognito `USER_PASSWORD_AUTH`）。不使用 Cognito `preferred_username` 别名。
2. **修改登录名是单个 DynamoDB 事务**：新 `LOGIN#` 条件写入、旧 `LOGIN#` 条件删除、Profile 版本递增。没有跨服务步骤，因此不存在“改名中途失败”的 pending 状态。契约中的 202／rename 操作接口保留，但当前实现总是同步返回 `done`。架构 §4.1 关于别名的步骤被本 ADR 取代。
3. **会话失效边界**：Profile 保存 `session_epoch`（整数）与 `sessions_valid_after`（UTC）。改密码、管理员重置、停用账号时两者同时更新（`sessions_valid_after` 取当前时刻的下一个整秒，因为 `iat` 只有秒精度；改密流程等到该边界后再签发新令牌），并调用身份服务撤销 refresh token（Cognito `AdminUserGlobalSignOut`）。请求鉴权时，`iat` 早于 `sessions_valid_after` 的 access token 一律 401；Actor 携带读取时的 `session_epoch`，提交事务再条件检查，覆盖“鉴权后、提交前被撤权”的窗口。
4. **令牌存放**：access token 只在浏览器内存；refresh token 放 `Secure; HttpOnly; SameSite=Strict; Path=/v1/auth` cookie。refresh／logout 使用双提交 CSRF：非 HttpOnly 的 `ledger_csrf` cookie 必须等于 `X-CSRF-Token` 头，且 `Origin` 必须在允许列表中。
5. **首次登录与重置**：身份服务返回 `NEW_PASSWORD_REQUIRED` 时，接口返回 `challenge`；完成改密后清除 `must_change_password`。改密前不能访问业务接口（`password_change_required`）。
6. **密码规则**：至少 10 位，同时包含字母和数字；不得等于登录名。Cognito 用户池策略在 D5 配置为同等或更严。密码与临时密码不写日志、不落库（本地替身只存 scrypt 哈希）。
7. **登录限流**：按登录名与来源 IP 各自固定窗口计数（DynamoDB 计数项，TTL 过期）：每 15 分钟同一登录名 10 次、同一 IP 30 次，超过返回 429。失败与成功都计数，避免借成功登录探测。
8. **令牌校验**：生产只接受配置的 Cognito issuer、app client（`client_id`）与 `token_use=access`，签名用 JWKS（RS256）。`LEDGER_ENV=local` 时使用本地替身的 RS256 密钥与 `local` issuer；生产配置拒绝该 issuer（ADR-0007）。
9. **系统管理员**：`is_system_admin` 只保存在应用 Profile，不使用 Cognito 组；创建账号、重置密码由应用调用身份服务管理接口，家庭管理员没有该入口。

## 影响

- AUTH-02 的“改名中途故障”场景变为“事务原子性”验证：新旧登录名不会同时有效或同时失效。
- 架构 §10 第 3 项中“登录别名冲突／变更恢复”改为验证 `USER_PASSWORD_AUTH` 流程与 refresh 撤销。
