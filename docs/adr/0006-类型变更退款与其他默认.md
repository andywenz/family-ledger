# ADR-0006 类型变更、退款关联及其他默认

日期：2026-10-04　状态：已采纳（用户决定）

## 决定

1. **改为退款**：已入账的支出可改为退款，但必须同时提供 `refund_of`（同家庭、有效、同币种的原消费），并通过额度检查；分类、消费方式自动沿用原消费，被改记录自身不能已有关联退款。
2. **退款不能改成其他类型**。需改时删除退款后重新录入。退款可修改金额（受额度限制）、日期（换快照）、备注；不可改币种、分类、方式（随原消费）。
3. **已有关联退款的消费**不可改币种、不可改类型、金额不得低于已退款累计；删除需先删除关联退款（界面提供“一并删除关联退款”的明确选项，在一个事务中完成）。恢复原消费不自动恢复退款；恢复退款要求原消费有效且额度充足。
4. **类型变更时的分类**：新类型对应的 kind 与原分类不符时，必须同时提交新的有效叶子分类（ADR-0002），否则 422。消费方式按新类型规则校验（支出必填，收入可选，其余不可填）。
5. **离开家庭的成员**：其历史账目仍显示其显示名，并标注“已离开”；不显示登录名。
6. **照片格式**：网站上传只接受 JPEG／PNG／WebP，单张 ≤10 MB，像素 ≤ 40 MP；HEIC 明确提示“请改为 JPEG”（iOS Safari 选择照片通常会自动转 JPEG）。飞书图片由平台资源 API 取得后按同规则校验。
7. **产品名**：沿用原型“小家账本”。
8. **候选不支持退款类型**：退款必须关联具体原消费，AI 无法可靠确定；模型识别到退款意图时在 `needs_review` 标注 `refund_intent`，界面提示用户从原消费的“退款”入口录入。
9. **业务日期范围**：不早于 2000-01-01，不晚于家庭时区当天＋1 天（容纳跨时区录入；系统只记录已发生事项）。

## 影响

ACC-12／ACC-14 的测试数据集按以上规则编写。
