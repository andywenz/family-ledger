# 部署说明

> 状态：**尚未部署**。以下命令中带 ☁️ 的步骤会创建或修改云资源，需要用户对具体账户与动作授权后执行。

## 0. 前置核对（一次）

1. ☁️ 目标 AWS 账户与身份：
   ```bash
   aws sts get-caller-identity --profile <目标账户 profile>
   ```
   核对账户 ID 与用户名；**不得使用课程账户或其凭证**。
2. Bedrock（Sydney）开通所选模型；模型选择以 `verification/model-eval/` 的比较结论为准。
3. 私人参数写入 `config/private/cdk.context.json`（git 忽略）：
   ```json
   {"account": "<12 位账户 ID>", "siteDomain": "<网站域名>", "alertEmail": "<备用通知邮箱>",
    "budgetUsd": "<NZD 15 按账单币种换算>", "modelId": "amazon.nova-pro-v1:0"}
   ```
4. ☁️ CDK bootstrap（Sydney 与 us-east-1，后者用于 CloudFront 证书）：
   ```bash
   cd infra && pnpm exec cdk bootstrap aws://<账户>/ap-southeast-2 aws://<账户>/us-east-1
   ```

## 1. 构建并校验制品（本地，可随时执行）

```bash
uv run python scripts/build_lambda.py
uv run python scripts/verify_artifact.py dist/lambda.zip dist/manifest.json --expect-commit "$(git rev-parse HEAD)"
pnpm --filter @family-ledger/frontend build
cd infra && pnpm exec cdk synth $(python3 -c "import json;print(' '.join(f'-c {k}={v}' for k,v in json.load(open('../config/private/cdk.context.json')).items()))")
```

工作区必须干净（manifest `dirty_worktree=false`），否则门禁拒绝。

## 2. 首次部署（☁️）

1. `pnpm exec cdk diff …`：审阅 IAM、删除、替换。重点确认表与桶为 Retain、无意外替换。
2. `pnpm exec cdk deploy --all …`：CloudFront 证书在 us-east-1 创建后，CloudFormation 会等待 DNS 验证——在 Cloudflare 添加控制台显示的 CNAME 验证记录（仅 DNS，关闭代理）。
3. 在 Cloudflare 添加网站域名 → CloudFront 分发域名的 CNAME（仅 DNS）。
4. Secrets Manager 中写入飞书 Secret JSON：`{"app_id","app_secret","verification_token","encrypt_key","tenant_key"}`。
5. 前端发布：`aws s3 sync frontend/dist s3://<SiteBucket> --delete`。
6. 读回：`curl https://<网站域名>/v1/health`，核对 `commit` 与 `artifact_digest` 等于 manifest。
7. 初始化（一次）：用部署输出执行
   ```bash
   AWS_PROFILE=<目标账户> AWS_DEFAULT_REGION=ap-southeast-2 \
   LEDGER_TABLE=<TableName> LEDGER_DELETION_TABLE=<JournalTableName> COGNITO_USER_POOL_ID=<UserPoolId> \
   uv run python -m ledger.ops.initialize --account <账户 ID> --admin <登录名> --name <显示名>
   ```
   命令先核对凭证账户、表与用户池，显示计划并要求输入 `INIT`；写入全局币种、最近 120 天 ECB 汇率与初始系统管理员，不创建家庭或账目、不导入历史。可重复执行（只补缺、不重置密码）。临时密码只在终端显示一次，按《管理员操作说明》「首发账号交付」处理。
8. 飞书开放平台：事件订阅 URL `https://<网站域名>/v1/integrations/feishu/events`，卡片回调 `…/cards`；开启加密，权限仅私聊消息与资源读取。

## 3. 后续发布（CI → 部署工作流）

1. 合并到 main，CI 生成 `release-<commit>` 制品。
2. 手动触发 `deploy` 工作流，填写 CI 运行 ID 与 commit；production 环境审批后执行门禁、diff、deploy、读回。

## 4. GitHub OIDC 部署角色（☁️，一次）

信任策略限定 `token.actions.githubusercontent.com`、`aud=sts.amazonaws.com`、`sub=repo:<owner>/<repo>:environment:production`；权限只够 CloudFormation 部署与 `cdk-*` bootstrap 角色的 assume。实际 subject 格式在启用前核实。
