## 独立核对方式

集成测试除检查用例返回值外，直接查询表项（`raw_items`）核对：账目条数、定位器指向、回执是否存在、退款累计 `refunded_minor` 与 `refund_ids`、回收站与删除日志，以及故障后整个家庭分区逐项不变。

## 故障与并发场景

- 4 线程同时对 100 元消费各退 40：恰好 2 笔成功，其余 `refund_exceeds_remaining`；读回累计 80.00。
- 2 线程同版本编辑：1 成功 1 `version_conflict`；读回 version=2。
- 读取后、提交前移除成员：提交事务内成员条件拒绝（`forbidden`），无账目、无回执。
- 读取后、提交前停用分类：条件失败→重读→`category_inactive`，无写入。
- 事务已提交但客户端超时：返回 `upstream_unknown`；`get_action` 查到原结果；同 key 重试返回原账目，表内仍只有一条。
- 事务后段定位器冲突：整个家庭分区逐项不变（含月版本、审计、回执）；修复后同 key 成功。

## 测试中发现并修复的问题

- `date.fromisoformat` 在 Python 3.11+ 接受 `20261004`；改为先用正则限定 `YYYY-MM-DD`。
- 空前缀分区查询被 DynamoDB 拒绝；`query_prefix` 对空前缀只用分区条件。
- 两处测试预期错误（逐笔舍入后的合计、按快照重算的金额），已按需求 §7 更正并注明原因。

## 覆盖限制（不能据此宣称）

- DynamoDB Local 不证明真实 DynamoDB 的事务冲突行为、IAM、PITR；生产 repository 需在 D5 真实验收。
- 尚无 HTTP 入口与身份服务：Actor 由测试直接构造，Cognito、cookie、CSRF 在 D2。
- 照片关联在 D1 显式拒绝（`照片关联将在 D2 启用`）；共享照片引用计数与 S3 清理在 D2。
- 汇率重算（FX-05）、导出（ACC-17）、AI 候选（CAT-03、AI-*）、飞书（FS-*）未实现。
- 性能假设：月清单每页重新读取整月、分类使用计数扫描家庭账目；适用于少量用户，数据量增长后需复核。
